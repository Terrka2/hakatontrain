# CityTriage — концепт

## Одним абзацем
**ИИ-оператор городских служб.** Обращения о проблемах в городе приходят потоком — система сама разбирает их вместо человека-диспетчера: склеивает жалобы об одной проблеме, объясняет приоритет каждой, помечает сомнительное, учитывает погоду и собирает бригадам маршруты на день — так, чтобы за один выезд закрыть несколько проблем рядом. Руководитель одной кнопкой утверждает план. Бригада на телефоне видит свой маршрут и отмечает «сделано» или «не могу» — и оператор тут же перестраивает план. С оператором можно разговаривать; его инструменты опубликованы по MCP.

## Задача хакатона → где это в продукте
Судьи оценивают ответы на четыре вопроса задачи. Каждый должен быть виден на экране.

| Вопрос из задачи | Блок | Экран |
|---|---|---|
| Какие проблемы требуют наивысшего приоритета? | B4 priority | Очередь приоритетов (F2) |
| Какие сообщения относятся к одной проблеме? | B3 clusters | Карточка проблемы: «почему склеено» (F2) |
| Какие факторы влияют на приоритет? | B4 `factors[]` | PriorityBar (F2) |
| Как эффективнее распределить ресурсы? | B6 dispatch + B8 fieldwork | Пульт руководителя (F3), экран бригады (F5) |

## Пользователи
- **Руководитель службы (supervisor)** — смотрит ленту действий оператора, разбирает спорные обращения, утверждает план. Экраны F2, F3, F4.
- **Бригадир (crew)** — телефон: маршрут, «приехал / сделано с фото / не могу с причиной». Экран F5.
- **ИИ-оператор** — не человек и не чат, а цикл (блок B0): по любому событию заново разбирает входящие и собирает или перестраивает черновик плана.
- Житель — только в дополнительном блоке (B7, F7, X1), если останется время.

## Граница самостоятельности ИИ
| Оператор делает САМ | Только человек |
|---|---|
| разбор и проверка обращений, склейка дубликатов, приоритет | утвердить план и отправить бригадам |
| пометить обращение «требует проверки» | принять или отклонить спорное обращение |
| собрать черновик плана; перестроить его после «не могу», смены погоды, новой аварии | — |

Любой результат оператора — **черновик**. Бригады видят только утверждённый план. Ошибся ИИ — отвечает человек, который нажал «Утвердить», и у него перед глазами было, что изменилось и почему.

## Что решает нейронка, а что математика
| Математика (детерминированно) | LLM |
|---|---|
| дубликаты, балл приоритета, маршруты, перестройка, правила погоды | понять запрос человека → намерение из закрытого списка + параметры по схеме |
| порядок шагов оператора (фиксированный граф) | извлечь признаки из текста обращения, оценить правдоподобие |
| | рассказать человеческим языком, что сделано и почему, — строго по данным инструментов |

LLM не считает маршруты и баллы и не выбирает себе инструменты свободно: граф и таблица ролей решают, что ей можно. Одинаковый вход → одинаковый план. При выключенном LLM (`LLM=off`) продукт работает целиком — просто говорит шаблонами.
«Оператор видит карту» = получает `UIState` (что выбрано, какая область, фильтры), а не картинку.

## Демо на 90 секунд
1. Импорт обращений → в ленте: «16 обращений → 13 проблем, 1 на проверку, собран план v1». Человек ничего не нажимал.
2. Три жалобы (RU + RO) про яму у лицея → одна проблема; видно, почему склеено.
3. Очередь: яма у лицея — 82, открытый люк у детсада — 80 («аварийный минимум»); полоса факторов.
4. «Нейрослоп» помечен «требует проверки» и в план не попал.
5. План: маршруты трёх бригад; четыре ямы на Албишоаре — один выезд. Руководитель жмёт «Утвердить».
6. Телефон бригадира: следующая остановка → «Не могу: нужна другая бригада». Через несколько секунд на пульте — план v2 и что изменилось.
7. «Пошёл ливень» голосом или текстом → оператор сам перестроил: асфальт отложен, упавшая ветка поднята; журнал объясняет каждое решение.

## Что берём готовым
| Блок | Готовое решение | Лицензия |
|---|---|---|
| Каркас: API, БД, авторизация, почта, фронт, Docker, CI | [fastapi/full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template) | MIT |
| Маршруты бригад (приоритеты, навыки, смены) | [VROOM](https://github.com/VROOM-Project/vroom) через [openrouteservice-py](https://github.com/GIScience/openrouteservice-py) | BSD / Apache-2.0 |
| Маршрут жителя | OpenRouteService directions | Apache-2.0 (клиент) |
| Погода | [Open-Meteo](https://open-meteo.com) | бесплатно для некоммерческого использования |
| Похожесть текстов RU/RO, поиск | [sentence-transformers](https://github.com/huggingface/sentence-transformers), scikit-learn | Apache-2.0 / BSD |
| MCP-сервер инструментов | официальный `mcp` Python SDK | MIT |
| Граф оператора | [LangGraph](https://github.com/langchain-ai/langgraph) | MIT |
| Карта | MapLibre GL + тайлы OSM | BSD |
| Модель обращения | стандарт Open311 GeoReport v2 | открытый стандарт |

Идеи (не код): [FixMyStreet](https://github.com/mysociety/fixmystreet) — «рядом уже сообщали»; [Mark-a-Spot](https://github.com/markaspot/mark-a-spot) — опасность как отдельный фактор, AI предлагает — человек решает; [CivicFix](https://github.com/TanishkaJanapure/CivicFix) — аддитивный 100-балльный приоритет (лицензии нет — код не копируем).

## Дополнительный блок — только если останется время
Навигатор жителя (B7, F7): маршрут A→B с проблемами по пути и кнопкой «всё ещё там». Мероприятия (X1): проблема на месте будущего забега важнее и получает дедлайн «до начала». Ядро от этих блоков не зависит; включаются флагом `OPTIONAL_BLOCKS=on`.

## Ограничения — говорим сами
Веса приоритета экспертные, не обучены на исходах · трудозатраты по категориям — оценки · демо-данные синтетические там, где организаторы не дали своих · проверка «нейрослопа» — эвристика, окончательно решает руководитель; «бригада не нашла проблему» — самый надёжный сигнал.
