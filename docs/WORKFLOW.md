# Как мы работаем

## Ветки
```
main  ← только стабильное, задеплоенное. Merge из dev: Арсений или Некит.
 └─ dev  ← интеграция. Сюда вливаются pair-ветки.
     ├─ pair/backend   Женёк + Пашок
     ├─ pair/llm       Некит
     └─ pair/frontend  Арсений + Лео
         └─ feat/<ID>-<кратко>   одна ветка = один блок = один уровень. Пример: feat/B4-priority-l0
```
- `feat/*` живёт **не дольше 4 часов**. Не успел — режь задачу, а не держи ветку.
- `pair/*` вливается в `dev` **каждые 3–4 часа и перед сном**. Перед этим — `git merge dev` в pair-ветку и зелёные тесты.
- Имя ветки обязано начинаться с `feat/<ID>-` — по нему CI определяет разрешённые пути.
- Изменение контрактов: ветка `contracts/<что>` → PR сразу в `dev`, одобряют Арсений **и** Некит.

## Цикл одной задачи
1. Открыл свой `docs/team/<Имя>.md`: там ветка и порядок блоков. Контракт — `docs/contracts/<ID>_*.md`, референсы — `docs/references/<ID>/`. Всё лежит в репозитории, никаких архивов.
2. Вставил контракт целиком в чат-нейронку (ChatGPT; нет — Qwen). В контракте уже есть инструкция планировщика: она выдаёт доску из 5–9 коротких задач и дальше даёт задачи по одной.
3. Копируешь задачу CLI-агенту (Antigravity / Codex / Claude Code). Агент сам читает `AGENTS.md` из корня репо. Результат проверки шлёшь планировщику: `готово N` + вывод. Доску из его ответа сохраняешь в `docs/status/<ID>.md` — она едет в PR вместе с кодом.
4. **Посмотрел diff.** Агент тронул файл вне «Разрешённых путей» — откати это изменение.
5. Запустил тесты сам. Попросил нейронку временно сломать реализацию — убедился, что тесты краснеют.
6. Агент дописал «Отчёт» в `docs/status/<ID>.md` и поставил ✅ уровню в твоём `docs/team/<Имя>.md`. Открыл PR в свою pair-ветку, тот же отчёт — в чат.
7. Ждёшь ревью. Следующий уровень не начинаешь; можно взять L0 другого своего блока.

## Ревью и merge
| Чей PR | Первое ревью | Одобряет merge |
|---|---|---|
| Пашок | Женёк | Некит |
| Женёк | Некит | Некит или Арсений |
| Некит | Женёк | Арсений |
| Арсений | Некит или Женёк | Некит |
| Лео | Некит (F6 — Арсений) | Арсений или Некит (не автор) |

- Одобрить свой PR нельзя. CI обязан быть зелёным.
- Ревью ≤ 15 минут на PR. PR больше 200 строк (без тестов) возвращается на разделение без чтения.
- Ревьюер проверяет: критерии приёмки закрыты тестами · пути не нарушены · модели контрактов не скопированы · есть откат на L0 · нет лишних зависимостей.
- После merge Арсений или Некит отмечают уровень в `docs/BLOCKS.md`.

## Сверки
Каждые 3 часа, 5 минут, по `docs/BLOCKS.md` и доскам `docs/status/*.md`: каждый показывает PR или экран, не рассказывает.
Нет PR за 3 часа → задача режется вдвое или уходит запасному из контракта. Без обсуждения.

## Если что-то сломалось в dev
1. Переключи блок на L0 переменной окружения — демо снова живо.
2. `git revert` merge-коммита. Чинить — в feat-ветке, не в dev.
