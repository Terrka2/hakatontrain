# Арсений: роль, ветка, блоки

> Скопируй этот файл в нейронку первым сообщением. Вторым — контракт текущего блока целиком.

## Роль в проекте
Интегратор и фронтенд. Карта и каркас экрана, пульт руководителя, панель ассистента. Держу карту блоков и утверждаю merge. Ко мне идут с вопросами по контрактам и когда что-то не стыкуется между блоками.

## Ветка
Рабочая ветка: **`pair/frontend`**. Под каждый блок и уровень: `git checkout pair/frontend && git pull && git checkout -b feat/<ID>-<кратко>`. PR открываешь в `pair/frontend`. В `dev` и `main` напрямую — нельзя.

## Мои обязанности по чужим блокам
- Запасной по блокам: F2, F5, F6. Если владелец выпал на 3 часа без PR — блок переходит ко мне.
- Первое ревью блоков: L1, L2, L3, F6. Ревью ≤ 15 минут: критерии приёмки закрыты тестами · пути не нарушены · модели контрактов не скопированы · есть откат на L0.

## Цикл одной задачи
1. Контракт целиком → планировщику. Он выдаёт доску из 5–9 задач L0 и дальше задачи по одной.
2. Задачу → CLI-агенту. Смотри diff: файл вне «Разрешённых путей» контракта — откати.
3. Проверку из задачи запусти сам, вывод → планировщику: `готово N`.
4. Все ✅ → планировщик даёт `ЗАДАЧА <ID>-QA`, агент сам проходит QA из контракта и чинит найденное. Ты QA не делаешь. Потом агент пишет «Отчёт» в `docs/status/<ID>.md`, ты открываешь PR в `pair/frontend` и кидаешь отчёт в чат.
5. Следующий уровень только после `L0 принят` от ревьюера. Пока ждёшь — L0 следующего своего блока.

## Куда идти с вопросами
- Не хватает поля в моделях или нужен файл вне своих путей → Арсений или Некит.
- Не понял контракт → владелец блока-соседа из таблицы в `docs/BLOCKS.md`, потом Арсений.
- Сломался `dev` → переключи блок на L0 переменной окружения, потом `git revert` merge-коммита.
